# QCP Web Frontend — المرحلة 3 من خطة تحويل Quick Cash Plus لأونلاين

نسخة ويب من واجهة Quick Cash Plus (Vite + React 19 + TypeScript)، منفصلة تمامًا عن مجلد الأوفلاين وعن [backend](../backend) — بتتصل بالباك إند عبر HTTP/WebSocket بدل Electron IPC.

## طريقة التشغيل

محتاج [backend](../backend) شغال على `localhost:4000` أولًا (`npm run dev` هناك)، وبعدين:

```bash
npm install
npm run dev
```

بيفتح على `http://localhost:5173`. تسجيل الدخول: **admin / admin123**.

## الفكرة الأساسية

كل شاشات الواجهة الأصلية (44 ملف، ~13,700 سطر) اتنسخت **زي ما هي بالظبط بدون أي تعديل** — لأنها كلها بتتكلم مع البرنامج عن طريق كائن عام واحد اسمه `window.api` (كان بيتحقن عبر Electron's contextBridge)، وكل شاشة بتنادي حاجة زي `window.api.customers.create(...)`.

الشغل الحقيقي في المرحلة دي كله في ملف واحد جديد: [`src/renderer/src/platform/webApi.ts`](src/renderer/src/platform/webApi.ts) — بديل كامل لـ`window.api` بنفس الشكل والأسماء بالظبط، لكن بدل `ipcRenderer.invoke(channel, ...)` بينادي `fetch('/api/rpc/' + channel, ...)` على الباك إند. `main.tsx` بينادي `installWebApi()` مرة واحدة عند الإقلاع يحط الكائن ده مكان `window.api` — وبعدها كل الشاشات القديمة تشتغل من غير ما تعرف إن الطبقة تحتها اتغيرت خالص.

## الفروقات عن نسخة الأوفلاين

| الميزة | الأوفلاين | الويب |
|---|---|---|
| تسجيل الدخول | يخزن `activeUser` في preload | يخزن JWT token في `localStorage`، بيتبعت كـ`Authorization: Bearer` مع كل نداء |
| "مين نفّذ العملية" (لسجل النشاط) | بيتبعت من الواجهة (`ACTOR_META_KEY`) | السيرفر نفسه بيحدده من التوكن الموثّق — أأمن، ومفيش داعي لمنطق إضافي هنا |
| تحديث لحظي (`onDataChanged`) | `ipcRenderer.on('data:changed')` | WebSocket على `/ws?token=...` |
| إعادة تشغيل البرنامج | `app.relaunch()` | `window.location.reload()` |
| مزامنة الأجهزة عبر الشبكة المحلية (`network.*`) | جهاز رئيسي/فرعي عبر LAN | **مفهوم متقاعد** — كل متصفح بيتصل بالسيرفر المركزي مباشرة، مفيش "جهاز رئيسي" تاني. القنوات لسه موجودة بترجع قيم افتراضية عشان أي شاشة قديمة تفضل شغالة، لكن مالهاش معنى حقيقي دلوقتي |
| دعم فني عن بُعد (AnyDesk/TeamViewer) | `shell.openExternal(protocol)` | `window.open(protocol)` — بيشتغل لو البرنامج مثبت فعليًا على جهاز المستخدم |

## اللي اتأكد منه فعليًا (مش افتراض) في متصفح حقيقي

- شاشة تسجيل الدخول بتحمّل بيانات المتجر (اسم/شعار) **قبل** تسجيل الدخول (قناة `settings:getStore` مستثناة من المصادقة بأمان — أول محاولة لعمل الاستثناء ده كانت فيها باگ أمني خطير: استخدام `:` جوه مسار Express بيتفسّر كـparameter بيفتح **كل** قنوات `settings:*` من غير مصادقة بالغلط؛ اتصلح في [server.ts](../backend/src/http/server.ts) بمطابقة نص حرفية بدل route pattern)
- تسجيل دخول حقيقي (admin/admin123) → JWT → لوحة تحكم بأرقام حقيقية من Turso
- الشريط الجانبي الكامل (18 موديول) ظاهر ومفلتر حسب صلاحيات المستخدم فعليًا
- إنشاء عميل جديد فعليًا من الواجهة → اتسجل في Turso → القائمة اتحدّثت لحظيًا

## مشاكل معروفة (بيئة التطوير، مش أخطاء في الكود)

- **`npm run build` (وحتى `npm run dev` مع Vite 5) كان بيفشل** لأن Windows Defender على الجهاز ده بيحجب/يمسح ملف `@rollup/rollup-win32-x64-msvc` الأصلي (native binary) باعتباره "فيروس" — false positive معروف. الحل المطبّق: تثبيت **Vite 4** (بيستخدم Rollup 3 اللي كوده JavaScript خالص من غير ملفات native، فمش بيتأثر بالمشكلة دي). لو حبيت الترقية لـVite 5 لاحقًا، لازم تستثني مجلد المشروع من فحص Defender بنفسك أولًا.
- console بيظهر فيه أخطاء WebSocket متكررة في وضع التطوير بس (`React.StrictMode` بيعمل mount/unmount مزدوج لكل effect عمدًا، فبتتقفل أول محاولة اتصال قبل ما تكتمل) — مفيش تأثير فعلي، الاتصال الحقيقي بينجح وبيفضل شغال (اتأكد بسكربت Node منفصل بيتصل مباشرة بالباك إند وعن طريق بروكسي Vite، الاتنين نجحوا).

## الطباعة عبر QZ Tray (المرحلة 4 — كل الأنواع ✅)

المتصفح لوحده مايقدرش يوصل لطابعة حرارية مباشرة، فالحل: [QZ Tray](https://qz.io) — برنامج مجاني صغير المستخدم لازم يركّبه بنفسه على جهاز كل فرع فيه طابعة (تركيب برنامج مش حاجة أقدر أعملها نيابةً عنه). لما يكون مثبت وشغال، صفحة الويب تقدر تبعتله أوامر طباعة عبر WebSocket محلي.

- [`platform/qzPrint.ts`](src/renderer/src/platform/qzPrint.ts) — الاتصال بـQZ Tray، طباعة HTML (`printHtmlViaQz`)، وفتح درج الكاشير بأمر ESC/POS خام (`openCashDrawerViaQz`).
- `window.api.print.*` بقت كلها بتعمل طباعة فعلية عبر QZ Tray: `receipt`, `quotation`, `stockPermit`, `shiftSummary`, `labels`, `kitchenTicket`, `openDrawer` — نفس الأسماء والتوقيعات القديمة بالظبط، الشاشات القديمة (POS، الفواتير، عروض الأسعار، الأذونات، الورديات...) بتستخدمها من غير ما تعرف حاجة اتغيرت.
- `window.api.print.preview*` (الإيصال، عرض السعر، الإذن، الوردية) بتفتح النتيجة في تاب جديد للمعاينة بس بدون طباعة (رابط Blob + نقرة على `<a>` بدل `window.open()` المباشر، عشان يتفادى حجب متصفحات كتير للنوافذ المفتوحة من كود).
- **ملحوظة أمان صادقة**: الاتصال دلوقتي بدون شهادة توقيع رقمي (unsigned). لإنتاج حقيقي على نطاق واسع الأفضل شهادة موقّعة من QZ Industries عشان الموافقة تبقى تلقائية بالكامل بدل ما QZ Tray يسأل المستخدم أول مرة — ده تحسين لاحق.

**اتأكدت كل الأنواع الستة بطباعة فعلية حقيقية على الطابعة** (مش بس توليد HTML) بعد ما المستخدم ثبّت QZ Tray فعليًا وشغّله: الإيصال، عرض السعر، إذن إضافة المخزون، ملخص الوردية، ليبل الباركود، وبون تجهيز المطبخ — كل واحد اتبعت فعليًا لطابعة النظام الافتراضية (Microsoft Print to PDF) وطلع ملف PDF حقيقي بكل بياناته صح.

**باگ حقيقي اتلقى واتصلح أثناء الاختبار ده**: طباعة الليبل عَلَّقت (hang) تمامًا من غير أي خطأ ظاهر — طلع إن `qz.print()` بيعلّق لو الـconfig اتعمل من غير "size" خالص (عكس Electron في الأوفلاين اللي كان بيتصرف عادي مع `@page: size:auto`). الحل: `widthMm` بقى إجباري في كل نداء طباعة — تفاصيل كاملة في [README الباك إند](../backend/README.md).

**فجوة معروفة**: طباعة بونات المطبخ التلقائية بعد "إرسال للمطبخ" في شاشة المطاعم (`OrderScreen.tsx`) مش موصولة لسه — كانت بتحصل تلقائيًا من السيرفر في الأوفلاين (مستحيل معماريًا دلوقتي)، ومحتاجة الشاشة تجيب إعدادات طابعة كل تصنيف بنفسها وتنادي `window.api.print.kitchenTicket()` لكل مجموعة بعد نجاح الإرسال. تفاصيل في [README الباك إند](../backend/README.md).

## اللي لسه ناقص

- ما تماش اختبار كل الـ18 موديول يدويًا — اتأكد من: تسجيل الدخول، لوحة التحكم، العملاء (قراءة+كتابة)، البيع (checkout حقيقي)، الفواتير + الطباعة (كل الأنواع)، عروض الأسعار، أذونات المخزون. الباقي (المخزون، التقارير، المطاعم، التوصيل...) لسه محتاج اختبار حقيقي واحد واحد.
- `npm run build` (نسخة إنتاج نهائية) لسه محتاج اختبار فعلي بعد حل مشكلة Defender.
- طباعة بونات المطبخ التلقائية في شاشة المطاعم مش موصولة لسه (فجوة موثّقة فوق).
- قنوات مش موصولة بالباك إند أصلًا (تصدير Excel/PDF، مرفقات، Google Drive — موثّقة في [README الباك إند](../backend/README.md)) هتفشل بوضوح لو اتستخدمت من هنا، مش هتكسر باقي الشاشة.
